## Story
As a visitor, I want to search and filter movies, so that I can find a specific title without browsing year by year.

## Origin
PRD story block, `**Added.**` marker. /ideate.

## Acceptance criteria
- [x] **AC1.** When a visitor enters a movie title in search, the system shows matching movies across all published years.
- [x] **AC2.** A visitor can filter the movie list by year and by genre.
- [x] **AC3.** When no movie matches the search or filter, the system shows an empty state instead of an error.

## Out of scope
Saved searches, search suggestions/autocomplete.

## Context
PRD: E01 / S-003. DESIGN: Search, search empty state. ARCHITECTURE: Next.js App Router + Prisma, `code/frontend`.

## Plan

Goal-backward from the three criteria. End state: a visitor opens the real `/search` screen (DESIGN 3.4), types a title into the autofocused input and sees matching movies drawn from every published year (AC1), narrows that grid with a year dropdown and a genre dropdown populated from real published data (AC2), and when nothing matches sees the "No movies match your search" empty state with the filters still editable rather than an error (AC3). This story only reads; it writes no data and touches no auth, so it stays unattended in sketch mode's lighter lane.

What already exists (checked, do not re-create): the Prisma schema with `Movie.title`, `Movie.genre`, and `Movie.year -> Year.published` (`code/frontend/prisma/schema.prisma`), the initial migration and Prisma client singleton (`src/lib/db.ts`), the canonical year reads (`src/lib/years.ts`), the reusable `PosterCard` (`src/components/poster-card.tsx`) and `Errnote` (`src/components/errnote.tsx`), and the working Vitest + Playwright harness. What is missing: the movie search reads, the search API route, the `/search` screen and its client filter component, and the tests. Note the S-003 branch base carries S-001 and S-004 only, not S-002, so there is no movie-detail route to link into; result cards render with the existing `PosterCard` shape, no href assumption.

The published gate is the load-bearing rule and it lives in the query layer, mirroring `years.ts`. Two identifiers are pinned so every layer agrees: `searchMovies({ q, year, genre })` and `getSearchFilters()`, both in `src/lib/movies.ts`. `searchMovies` filters `where: { year: { published: true } }` first (so an unpublished year's movies never surface anywhere in search, matching S-001-AC3), then applies a case-insensitive `title contains q` when `q` is non-empty (AC1), an exact `year.year` match when a year is chosen and an exact `genre` match when a genre is chosen (AC2), with an empty result set being a valid, non-error outcome (AC3). `getSearchFilters` returns the DISTINCT published years and DISTINCT genres (ARCHITECTURE.md note: no `Genre` table, filter options come from `DISTINCT genre`) so the dropdowns offer recognition over recall (DESIGN 3.4), never free text.

The screen splits server and client per ARCHITECTURE.md section 3: `/search` is a Server Component that loads `getSearchFilters()` once to populate the dropdown options, then renders a client component that live-queries `GET /api/movies?q=&year=&genre=` as the visitor types and filters (the live re-query pattern the architecture names for S-003). The route handler is the only new API surface; it parses the three query params, calls `searchMovies`, and returns `{ movies: [...] }`, or `{ error }` with a 4xx/5xx on failure per the error-handling convention.

`ui_surface: true`. All three criteria are observed through the real search screen and the real input mechanisms (the text input and the two `select` dropdowns), which Playwright can drive automatically, so the story stays unattended with a durable e2e test rather than supervised. The durable proof is the Playwright spec in T6, which seeds published and unpublished years across multiple genres, then drives the real browser: types into the actual search input and asserts matches span published years while an unpublished year's title never appears (AC1), changes the real year and genre `select`s and asserts the grid narrows (AC2), and types a no-match query to assert the empty state renders instead of an error (AC3).

How this story is proven. The command scripts/test.sh runs.

- Unit (T5, `tests/unit/movies.test.ts`, Vitest against real Postgres): seed two published years and one unpublished year with movies across at least two genres. `S-003-AC1` asserts a title query returns matches from every published year and never a movie from the unpublished year. `S-003-AC2` asserts year-only, genre-only, and combined year+genre filters each narrow the set to exactly the expected rows. `S-003-AC3` asserts a non-matching query returns an empty array (not a throw), and that `getSearchFilters` returns only published years and the DISTINCT genre set.

- 2026-09-08 | round 1 | D1 | high | fixed | Vitest DB test files ran concurrently and stomped each other's fixtures
  Adding tests/unit/movies.test.ts as a second real-Postgres-backed test file
  alongside tests/unit/years.test.ts exposed a latent bug: Vitest's default
  file parallelism runs both files' `beforeEach`/data-layer code against the
  one shared database at the same time, so one file's `Year.year` insert (or
  its `deleteMany` reset) could race another file's, tripping the unique
  constraint on `Year.year` intermittently. Set `fileParallelism: false` in
  `code/frontend/vitest.config.ts` so unit test files run sequentially; tests
  within a file are unaffected. Trivial, in-repo-only fix, no task added.
- 2026-09-08 | round 1 | D1 | high | fixed | Playwright e2e specs raced on the same shared Postgres tables
  Same root cause as above, one layer up: `tests/e2e/browse.spec.ts` and the
  new `tests/e2e/search.spec.ts` each do an unscoped `deleteMany()` in
  `beforeAll`/`afterAll` against the shared dev database, and Playwright's
  default `fullyParallel: true` ran them as concurrent workers, so one spec's
  cleanup could wipe another spec's in-flight fixtures regardless of which
  year numbers each used. Set `fullyParallel: false` and `workers: 1` in
  `code/frontend/playwright.config.ts` so spec files run one at a time.
  Confirmed the full suite (11 Vitest + 10 Playwright) is green after the
  change. Also picked disjoint year values in `tests/e2e/search.spec.ts`
  (5994/6010/6099) as a belt-and-suspenders measure against future test
  files reintroducing the race.
