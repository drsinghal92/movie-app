KaizenOS Pipeline

Idea to shipped app

The complete KaizenOS journey, walked through a worked example. The product is KaizenDo, a to-do app on the demo tier, sized at three epics and six stories. Every step below names the command you run, the agent it invokes, and the artifact that agent leaves behind. Truth lives in files, not chat.

ACT II

The build loop

One story per run. /next --all drains the backlog, --unattended runs it overnight and skips supervised stories. The loop below runs six times for KaizenDo, once per story. It never merges.

07
/nextInside one run, story S-001 Add a task
Planplanner Opus

Plans the story goal-backward into backlog/E01/S-001.md and rates confidence 1 to 10 against the acceptance criteria. Below the threshold it blocks the overnight run instead of guessing.

Buildbuilder Fable 5

Implements the thin vertical slice with tests in code/, on a task branch. Drift rules apply, trivial gaps get fixed and logged (D1, D2), contract changes stop the run (D3), out-of-scope ideas become new stories (D4).

Mechanical gatescripts/gate.mjs, no LLM

Lint, typecheck, and scripts/test.sh. Deterministic, cheap, runs every time.

QA gateqa SonnetPASS / CONCERNS / FAIL

Read-only. Reruns the tests and checks each acceptance criterion. A FAIL blocks the commit.

Security passsecurity-reviewer Sonnetproduction tier, flagged surfaces only

OWASP-style pass when a story touches auth, payments, or user data. KaizenDo runs demo tier in sketch mode, so this step is skipped and the loop says so.

Gate file, commit, PR

The verdicts land in docs/gates/S-001.yml, the branch is committed, and a PR opens. State moves in files, docs/STATE.md keeps the resumable pointer.

Adversarial reviewpr-reviewer Opusdemo tier, on demand via /pr-review

A 4-family reviewer hunts the blind spots the 5-family builder shares with itself, then posts the review on the PR. Never merges. Production tier runs it inside the loop automatically.

Track and learnnarrator Haiku

The run is appended to logs/PROGRESS.md, harvested lessons go to docs/CONVENTIONS.md, and the queue advances.

ACT III

Your clean morning

The agents worked the night. You review, decide, and close the loop.

08
/standupMorning digestyou + main loop

What shipped overnight, which PRs are open and what their reviews said, what is blocked, and what needs your call. For KaizenDo that is five green PRs and one held story, S-006, waiting on your answer about search scope.

Delivers
  • the digest read over coffee, decisions in minutes
09
/mergeLand the stackmerger Sonnet

Demo tier delegates merging, agent-on-green. The merger lands the gate-green, reviewed PR stack bottom-up, PR #1 through #5, verifies main after each, and reconciles ROADMAP.yaml and STATE.md. On production tier this step stays human.

Delivers
  • main five stories landed, verified green
10
/feedbackand/reviseThe loop runs both waysyou + main loop

You use KaizenDo and notes come back. /feedback routes each note by altitude, a copy tweak becomes a fix, a new idea becomes a story seeded into E03, a contract change stops for your call. /revise re-opens exactly one shipped story, say S-003 because check-off needs an animation, amends it, and sends it back through the same gates. You answer the S-006 question and /next picks it up.

Delivers
  • backlog/ new and amended stories, same loop, no side doors
